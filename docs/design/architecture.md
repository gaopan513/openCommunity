```
│         Vue 3 SPA + Element Plus + Vite                  │
└────────────────────────┬────────────────────────────────┘
                         │ HTTP / REST API (JSON)
                         ▼
┌─────────────────────────────────────────────────────────┐
│                   Nginx（反向代理）                       │
│         静态文件服务 + API 转发 + 媒体文件                 │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│              Django + DRF（后端 API 服务）                │
│                                                         │
│  ┌─────────┐ ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │  users  │ │merchants │ │secondhand│ │     qa     │  │
│  └─────────┘ └──────────┘ └──────────┘ └────────────┘  │
│  ┌────────────┐ ┌──────────────┐ ┌──────────────────┐  │
│  │ discussion │ │ housekeeping │ │  admin_system    │  │
│  └────────────┘ └──────────────┘ └──────────────────┘  │
│  ┌──────────────────────────────────────────────────┐  │
│  │              common（公共组件层）                   │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│              PostgreSQL / SQLite（数据层）                │
└─────────────────────────────────────────────────────────┘
```

## 后端分层架构

每个 Django App 内部遵循三层结构：

```
URL 路由层 (urls.py)
    ↓
视图/序列化层 (views.py + serializers.py)
    ↓  权限校验、参数验证、响应格式化
业务逻辑层 (services.py)
    ↓  核心业务处理、状态流转
数据模型层 (models.py)
    ↓  ORM 操作、数据持久化
数据库
```

## 认证与权限流程

```
客户端请求
    ↓
携带 JWT Token (Authorization: Bearer <token>)
    ↓
SimpleJWT 中间件验证 Token 有效性
    ↓
DRF Permission 类检查角色权限
    ↓
通过 → 执行业务逻辑
拒绝 → 返回 401/403
```

**角色权限矩阵**：

| 资源 | 游客 | 居民 | 商家 | 管理员 |
|------|------|------|------|--------|
| 浏览公开内容 | ✓ | ✓ | ✓ | ✓ |
| 发帖/评论/点赞 | ✗ | ✓ | ✓ | ✓ |
| 发布二手商品 | ✗ | ✓ | ✗ | ✓ |
| 商家入驻/管理 | ✗ | ✗ | ✓ | ✓ |
| 发布活动 | ✗ | ✗ | ✓ | ✓ |
| 预约家政服务 | ✗ | ✓ | ✗ | ✓ |
| 服务商管理 | ✗ | ✗ | ✓* | ✓ |
| 内容审核/用户管理 | ✗ | ✗ | ✗ | ✓ |

*注：家政服务商使用商家角色扩展权限

## 数据流设计

### 商家入驻流程
```
商家提交申请 → 状态:pending → 管理员审核 → 通过:approved / 驳回:rejected
                                              ↓
                                        商家上线展示
```

### 二手商品状态流
```
发布 → 在售(on_sale) → 已预订(reserved) → 已售出(sold)
                    ↘ 已下架(off_shelf)
```

### 家政预约状态流
```
居民提交预约 → 待确认(pending) → 服务商确认 → 已确认(confirmed)
                                    ↓ 拒绝
                                 已拒绝(rejected)
已确认 → 服务中(in_service) → 已完成(completed) → 已评价(reviewed)
```

## API 设计规范

- 基础路径：`/api/v1/`
- 资源命名：复数名词（`/api/v1/merchants/`）
- 标准动作：GET（列表/详情）、POST（创建）、PUT/PATCH（更新）、DELETE（删除）
- 嵌套资源：`/api/v1/merchants/{id}/activities/`
- 分页：`?page=1&page_size=20`
- 筛选：`?category=dining&status=active`
- 排序：`?ordering=-created_at`
- 响应格式：`{ "code": 0, "message": "success", "data": {...} }`

## 文件存储方案（MVP）

```
media/
├── avatars/          # 用户头像
├── merchants/        # 商家图片（营业执照、店铺照片）
├── products/         # 二手商品图片
├── posts/            # 帖子图片
├── activities/       # 活动图片
└── housekeeping/     # 家政服务图片
```

上传限制：单文件 ≤ 5MB，支持 jpg/jpeg/png/webp，商品/帖子最多 9 张。
