## 技术难点分析

### 难点 1：多角色权限体系
- **挑战**：4 种角色（游客/居民/商家/管理员）权限差异大，商家和服务商又有类似但不同的权限
- **方案**：Django 内置 Group + Permission 机制 + DRF 自定义 Permission 类
- **风险**：低。Django 的 auth 系统成熟稳定

### 难点 2：多套状态流转
- **挑战**：商品状态（在售→已预订→已售出）、预约状态（待确认→已确认→服务中→已完成→已评价）、审核状态（待审核→通过/驳回）
- **方案**：使用 django-fsm 或手动实现状态机，配合模型方法约束合法转换
- **风险**：低。状态数量有限，逻辑清晰

### 难点 3：图片上传与管理
- **挑战**：多个模块需要图片上传（商家照片、商品图片、帖子图片），需要限制类型和大小
- **方案**：Django ImageField + Pillow 验证 + 本地 Media 存储（MVP）
- **风险**：低。后续可平滑迁移至 OSS

### 难点 4：评价/评分系统复用
- **挑战**：商家评价、家政服务评价结构类似但关联不同模型
- **方案**：使用 Django GenericForeignKey 实现通用评价模型，或为每个模块独立建模（MVP 推荐独立建模，降低复杂度）
- **风险**：低

### 难点 5：前端方案选择
- **挑战**：MVP 需要快速出活，但也要为后续小程序做准备
- **方案对比**：见下方技术路线选项
- **风险**：中。前后端分离方案前期投入大，但后期扩展性好

## 技术路线选项

### 方案 A：Django 模板 + Bootstrap（传统全栈）

**架构**：Django 模板渲染 + Bootstrap 5 + 少量 jQuery/Alpine.js

**优点**：
- 开发速度最快，前后端一体
- 无需处理跨域、API 版本等问题
- Django Admin 直接作为管理后台
- 部署简单，单个 Django 服务即可

**缺点**：
- 前后端耦合，后续迁移小程序需要重写前端
- 交互体验不如 SPA
- 前端代码组织性较差

**适合场景**：追求最快交付、团队熟悉 Django 模板

### 方案 B：Django REST API + Vue 3 SPA（前后端分离）⭐ 推荐

**架构**：Django + DRF 提供纯 API，Vue 3 + Vite + Element Plus 构建 SPA 前端

**优点**：
- 前后端完全解耦，API 可直接复用给小程序
- 交互体验好，组件化开发效率高
- Element Plus 提供丰富的后台管理组件
- 代码组织清晰，可维护性强

**缺点**：
- 前期搭建工作量略多（需要配置跨域、路由等）
- 需要同时维护两个项目
- 部署需要分别处理前后端

**适合场景**：有后续小程序规划、注重用户体验和代码可维护性

### 方案 C：Django REST API + React SPA

**架构**：与方案 B 类似，前端使用 React + Ant Design

**优点**：
- React 生态更大，组件库选择多
- Ant Design 后台管理方案成熟

**缺点**：
- React 学习曲线略高于 Vue
- 对于管理后台类项目，Vue + Element Plus 开发效率通常更高
- 国内社区 Vue 资源更丰富

**适合场景**：团队更熟悉 React

---

## 推荐结论

**推荐方案 B（Django + DRF + Vue 3）**，理由：
1. 用户明确后续要做小程序，前后端分离的 API 可直接复用
2. MVP 阶段 Element Plus 能快速搭建管理界面
3. Vue 3 上手快，组件化开发效率高
4. 代码结构清晰，适合模块化开发流程
